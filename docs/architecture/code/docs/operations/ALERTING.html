Alerting

How an incident reaches a person, and how that path is kept honest.

services /metrics ─┐
backup exporter ───┼─► Prometheus ── rules (observability/alerting.yml) ──► Alertmanager ──► Slack #alerts / #alerts-warning
Alertmanager ──────┤                                                                     ├─► PagerDuty (critical)
Prometheus itself ─┘                                                                     └─► dead man's switch (Watchdog, every minute)

Configuration

What Where
Rules observability/alerting.yml, copied into the K8s ConfigMap prometheus-config (deploy/k8s/infra/prometheus.yaml)
Routing observability/alertmanager.yml, copied into the K8s ConfigMap alertmanager-config (deploy/k8s/infra/alertmanager.yaml)
Credentials, K8s Secret alertmanager-credentials (keys SLACK_WEBHOOK_URL, PAGERDUTY_ROUTING_KEY, DEADMAN_URL), written by deploy.yml from the GitHub environment secrets ALERTMANAGER_SLACK_WEBHOOK_URL, ALERTMANAGER_PAGERDUTY_ROUTING_KEY, ALERTMANAGER_DEADMAN_URL
Credentials, compose one file per key in ALERTMANAGER_CREDENTIALS_DIR (default observability/alertmanager-credentials/, git-ignored)

Alertmanager reads the credential files when it sends, so a changed Secret needs no restart. A production deploy fails without the Slack webhook and the dead man's switch; staging only warns. Without a PagerDuty key, critical alerts still reach Slack #alerts (they are routed to both).

Dead man's switch

Watchdog always fires. Alertmanager sends it every minute to DEADMAN_URL, a heartbeat check of an external service (healthchecks.io, Dead Man's Snitch, Better Stack...) set to page when no heartbeat arrives for ~5 minutes. It is the only alert that still works when Prometheus, Alertmanager, the cluster or Slack is down: configure that external check to notify someone directly (email, SMS, phone), not through this Alertmanager.

The first run of these rules on a healthy-looking compose stack (2026-10-28) caught two incidents nobody had seen: the broker-message subscriber endpoint never answered (every delivery to trader-trainer timed out, was retried 10 times and dead-lettered: ~1/3 of the market data), and message-manager ignored DLQ_LOCAL_FALLBACK_PATH (in K8s the dead letters were written to the read-only root filesystem: lost). Both are fixed.

Writing a rule

  • Aggregate before dividing: sum by (job) (rate(errors[5m])) / sum by (job) (rate(all[5m])). Dividing raw series matches each 5xx series with itself and reports 100% on a single error.
  • A ratio whose numerator may not exist (no success yet, nothing published) needs (numerator or denominator * 0), otherwise it never fires.
  • histogram_quantile needs sum by (job, le) and never returns more than the largest finite bucket: the HTTP histogram goes up to 30s.
  • Every rule change goes with a case in tests/alerts/alerting.test.yml (bash tests/alerts/run.sh, CI job observability). The same tests fail on the rules as they were before 2026-10-28.
  • scripts/observability-gate.mjs keeps compose and K8s identical (rules and Alertmanager config), checks that every metric a rule reads is emitted, and refuses inline receiver credentials.
