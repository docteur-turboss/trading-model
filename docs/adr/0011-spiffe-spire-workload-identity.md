# ADR-0011: SPIFFE/SPIRE Workload Identity for Inter-Service Authentication

**Status:** Accepted
**Date:** 2026-09
**Supersedes:** [ADR-0005](./0005-mtls-security.md) (issuance & identity model), [ADR-0009](./0009-certificate-utils-structure.md) (custom certificate format)

## Context

ADR-0005 established mutual TLS backed by an in-house `certificate-authority` service. In practice the model drifted from the intent:

- The CA issues **non-standard certificates**: a base64-JSON envelope (`{body, signature, issuerCert}`) wrapped in `-----BEGIN CERTIFICATE-----` armor, produced by `packages/certificate-utils`. These are not parseable as X.509 by standard TLS stacks, OpenSSL, or SPIRE.
- No service in production actually authenticates against the CA: the live trust anchor is a **single shared** self-signed bundle (`./certs`) generated by `scripts/generate-certs.sh` and mounted into every container — a single shared identity, no per-service attestation.
- The CA signs CSRs **without verifying the CSR signature or tying the request to the caller's identity**; bootstrap tokens, nonces, proof-of-possession, distributed locking, key rotation, audit, and OIDC are implemented but never wired into the running container.
- Consumer code already understands SPIFFE IDs (`packages/common/src/utils/spiffe.ts`, `mtls-auth` prefers the certificate SAN), but nothing issues SPIFFE-valid identities.

SPIFFE/SPIRE is the industry-standard workload identity model: short-lived X.509 SVIDs carrying a `spiffe://` URI SAN, issued after **workload attestation** (the server verifies the workload's identity from the platform, not from a self-reported `serviceId`).

## Decision

Replace the in-house CA and the shared static certificate bundle with a **SPIRE** deployment (SPIFFE) as the single source of workload identity, and consume SVIDs **as files** via a `spiffe-helper` sidecar.

### Identity scheme

- Trust domain: `spiffe://trading-model.local`
- SVID SPIFFE ID shape: `spiffe://trading-model.local/ns/<namespace>/sa/<service>` where `<service>` is the **canonical service name** and the last path segment (already what `extractServiceName` reads).
- The canonical service name list in `packages/common/src/config/workload-identity.ts` becomes the single source of truth for service identities (K8s SA names, SPIFFE entries, ACL, discovery registration), superseding the diverging `ServiceInstanceName` / `KnownService` / compose `SERVICE_NAME` vocabularies (migration keeps a temporary alias map).

### SVID consumption

- Each workload runs a `spiffe-helper` sidecar that reads the SPIRE Agent Workload API (Unix socket) and writes `svid.pem`, `svid_key.pem`, and the trust bundle to a shared volume.
- Server-side TLS already hot-reloads certificate files (`packages/server-utils/src/infrastructure/tls-watcher.ts`) → no change for inbound TLS.
- Outbound clients must (a) reload key/cert/bundle on rotation and (b) disable Node's default hostname verification (`checkServerIdentity`) because SVIDs carry only a `spiffe://` URI SAN; trust comes from the SPIFFE trust bundle, and the peer's expected SPIFFE ID is enforced at the application layer.

### Target environments

- **Kubernetes (staging/production):** SPIRE Server (HA, MySQL datastore using the platform's existing MySQL) + SPIRE Agent DaemonSet with the `k8s_psat` workload attestor. Registration entries map each Deployment's service account to its SPIFFE ID.
- **Docker Compose (dev/CI):** single SPIRE Server + SPIRE Agent using the `docker` workload attestor (selectors on compose service labels), same SPIFFE ID scheme. CI fallback: join-token attestation when a privileged Docker socket is unavailable.

### Decommissioning

- `services/certificate-authority`, `packages/certificate-client`, the custom certificate/CSR format in `packages/certificate-utils`, the CA HTTP/WSS API, CRL/revocation endpoints, and `ca.*` events are **removed**.
- Revocation is handled by SPIRE entry/agent lifecycle (SVID rotation) instead of CRL.
- `./certs`, `scripts/generate-certs.sh`, the `ca-keys` volume, `trading-model-tls` / `trading-model-ca-keys` secrets, nginx `proxy_ssl_verify off`, and the CA backup/rotation jobs are removed or repointed at the SPIRE datastore.

## Alternatives Considered

| Alternative                    | Reason for Rejection                                                            |
| ------------------------------ | ------------------------------------------------------------------------------- |
| Keep & fix in-house CA         | No workload attestation; identity is self-reported; custom (non-X.509) format   |
| Vault PKI                      | No workload attestation; operational complexity; would still need custom wiring |
| cert-manager / istio          | K8s-only, no SPIFFE identity; heavier mesh than needed                           |
| Native Workload API client in Node | Larger dependency/maintenance surface than a file-writing `spiffe-helper`   |
| Static per-service certs       | No automated rotation, no attestation, no short-lived SVIDs                     |

## Consequences

### Positive

- Real workload attestation: a service can no longer claim an arbitrary `serviceId`.
- Short-lived, automatically rotated X.509 SVIDs with standard `spiffe://` URI SANs.
- One trust anchor per environment (SPIRE bundle); per-service identity replaces the shared cert.
- Authorization (ACL middleware) can finally be enforced with trustworthy identities.
- Removes a large amount of dormant/dead CA code and the non-standard crypto format.

### Negative

- New operational dependency (SPIRE Server/Agent) on both K8s and Compose.
- Docker Compose attestation requires a privileged Docker socket (CI caveat, join-token fallback).
- Hostname verification must be disabled on outbound clients in favour of trust-bundle + app-layer SPIFFE ID checks.

### Mitigations

- File-based SVID consumption reuses the existing TLS watcher → minimal per-service code change.
- `checkServerIdentity` override is centralized in the shared outbound TLS configuration.
- Phased rollout: identity primitives → SVID file reload → SPIRE infra → decommission CA → enforce ACL.
