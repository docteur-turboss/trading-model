# ADR-0087: Paper Decision Consumer (ADR-0049 Option C)

**Status:** Accepted
**Date:** 2026-11
**Related:** [ADR-0049](./0049-downstream-context-for-models-and-signals.md) (option C), [ADR-0064](./0064-risk-and-execution-context-before-order-flow.md) (Risk/Execution), [ADR-0069](./0069-model-admission-verdict-on-the-test-segment.md) (admissible), [ADR-0027](./0027-audit-chain-verification-and-anchoring.md) (audit), [ADR-0030](./0030-mt4-point-in-time-features-and-success-criteria.md) (point-in-time), [ADR-0079](./0079-replay-window-in-the-model-manifest.md) (replay)
**Verified by:** `services/decision-consumer/tests/unit/decide.spec.ts` (non-admissible or non-promoted model: no intent; same bar and model: same decision id; rejection counted by reason), `packages/model-runtime/tests/replay.spec.ts` (last-bar decision), `tests/contract/decision-consumer-routes.spec.ts` (real client against the real intents route, other identities 403), `services/risk-execution/tests/unit/handlers.spec.ts`, `packages/http/tests/unit/adapters/inbound/acl-config.spec.ts`, `tests/alerts/alerting.test.yml`, `packages/http/tests/unit/model-api/model-clients.spec.ts` (shared trainer and scraper clients), `bun run api:check`

## Context

ADR-0049 chose option B (offline `model-evaluator`) and left option C (paper trading) for after the Risk/Execution context existed. `risk-execution` exists (ADR-0064) but no decision reaches `POST /intents` (issue #2318). The owner decided the four open points on the issue (2026-11-23).

## Decision

1. **New service `decision-consumer`**, with its own SPIFFE identity and `INSTANCE_ID`. `model-evaluator` (offline replay, no side effect) keeps an SVID that cannot send an order. The ACL of `risk-execution` lists `risk-execution` (operator, from the pod) and `decision-consumer`; any other identity gets 403. It never holds a broker key, calls a broker, reads or changes the kill switch, or chooses the mode (ADR-0064 §1, §5, §6): paper is the only mode of `risk-execution`.
2. **Promotion by configuration.** `PROMOTED_MODELS=symbol@version,…` in `decision-consumer.properties`, one version per symbol: the pull request is the review and rollback. A model decides only if its manifest says `admission.admissible: true` (ADR-0069: admissible is eligible, not promoted). When it loads a promoted model (manifest, then weights, sha256 against the manifest and the `x-model-sha256` header, ADR-0049 §1.2) it publishes `risk.promotion.loaded` (symbol, version, sha256) for the audit chain through message-manager. A refused publication means no decision for that model until it succeeds (fail closed). No `training.model.published` subscription: the list is explicit, the manifest is read from the trainer at start and retried every pass, so the event adds nothing and no bus Redis user is created. The trainer lists the consumer in `MODEL_DOWNLOAD_CALLERS`.
3. **Sizing by `share`.** The agent of `model-runtime` plays the model greedily on a simulated wallet over the last `DECISION_WINDOW_BARS` closed bars (last-bar decision); the order is the wallet's position change on the last bar, so the `share` of the action set and the model's exposure cap (`riskLimits.maxExposureFraction`, 10 % at most since #2194) apply as in the replay (ADR-0066, ADR-0079). The simulated wallet starts at the first bar of the window: the same window gives the same answer. `risk-execution` stays the only guard; the local cap is a belt. Limit: features normalise from the first bar of the window, not of the training window. Before a sale the consumer reads the real paper position from `GET /positions/:symbol` of `risk-execution` (ACL: `decision-consumer` only, 403 for any other identity; the `/admin/*` routes stay operator-only, ADR-0064 §5): the quantity is bounded by that position and nothing is sent when it is flat. A failed read sends no intent and is retried at the next pass. A buy is still sized on the simulated wallet, which drifts from the paper one as the window slides: one while the real position is at its cap is rejected by `risk-execution` (`instrument_exposure`, `global_exposure`; `risk_orders_total`), counted by `DecisionIntentsRejected`.
4. **Symbols and cadence.** Every promoted model, at the interval of its manifest replay window (1 minute or 1 day, the intervals the evaluator reads). A pass every `DECISION_TICK_MS` decides once per closed bar. Candles come from the existing financial-scraper routes (ADR-0030: nothing after the bar's close).
5. **Intent.** Body of `POST /intents` as in ADR-0064 §1: instrument, side, quantity, reference price (the bar's close) and its time (the bar's close time), decision id `symbol@version:<bar open ms>`, source model. Same bar and model give the same id, so a restart or redelivery is deduplicated by `risk-execution` (§2-§3). A rejection is a result: counted in `decision_intents_total{outcome="rejected",reason}` and logged, never retried differently. `limitPrice` is not sent (the simulated broker fills at market).
6. **Types.** The request schema is declared in the client until #1904 moves `Intent` to `@trading-model/contracts`.

## Consequences

- One more service (compose, K8s, release matrices, SPIRE entry). Out of the box `PROMOTED_MODELS` is empty: nothing decides, and `risk-execution` keeps seeing no traffic.
- The trainer and scraper clients are shared with `model-evaluator` (`@trading-model/http/model-api/*`, each service passes its address lookup and manifest schema): one implementation of the sha256-checked artefact read.
- A model that reads signals (ADR-0081) as network inputs is not supported by this first version: only candle features.
